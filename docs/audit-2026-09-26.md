# StreetFun audit follow-up — 26 September 2026

Scope: fix findings 1–5 and 7 from the preceding audit and review the resulting changes. Finding 6 was deliberately excluded by the project owner. Changes are local and have not been committed, pushed, or deployed.

## Findings and resolution

| Finding | Status | Protection |
| --- | --- | --- |
| 1. Unrestricted settlement market and ineffective price floor | Fixed in source; program upgrade required | Both legacy and DBC settlement require an administrator-approved market and an unexpired minimum net exchange rate. Creator calls obey the same floor. The contract checks actual receipt after the swap. |
| 2. Donations and external burns block legacy graduation | Fixed in source; program upgrade required | Settlement spends accounted reserves, preserves unsolicited surplus, checks balance deltas, and accepts externally reduced mint supply without permitting inflation. |
| 3. Production mock flag enables public database writes | Fixed | The public mock recording route rejects production requests before accessing storage, even with the mock flag enabled. |
| 4. Public launch confirmation can overwrite token imagery | Fixed for new launches; legacy metadata protected | The signed DBC URI commits to the image and description. Confirmation rejects changed content. Confirmations of older launches cannot update unsigned image or description fields. |
| 5. Retrying an uncertain launch creates a second mint | Fixed | Persist the signed transaction identifier before broadcasting. Block replacements, coordinate tabs, and recover the same launch and indexing operation. Clear unresolved records only after verified success, final failure, or finalized expiry with an absent mint. |
| 6. Devnet collateral presentation and headline valuation | Unchanged by request | No change to those labels, provider marks, or headline valuation behavior. |
| 7. Treasury presents stale indexed holdings as current | Fixed | Holdings come from verified live token/vault snapshots. RPC failures return unavailable; the browser explicitly dates any retained snapshot. Indexed holdings are no longer preferred over live balances. |

The follow-up review also found and fixed a related replay bug: indexing the original DBC launch could reset the token's graduated status. The indexer now uses the current on-chain registry, and a regression test covers replay after graduation.

## Verification

- Production build and TypeScript checks pass; no warnings in the Next.js production build.
- 76 offline application tests pass, including metadata tampering, production write rejection, recovery after an accepted-but-timed-out broadcast, failed indexing retries, blocked browser storage, concurrent launch protection, finalized expiry, and treasury verification failure.
- 14 native Rust tests pass, including policy expiry, substituted markets, price rounding, and DBC caller timing. Existing Anchor/Solana conditional-compilation warnings remain.
- The SBF program and IDL build successfully. On a fresh isolated local validator, 14 integration tests pass using the compiled StreetFun program and the Meteora DAMM v2 program. The lifecycle rejects an unauthorized policy update and a dust minimum, then successfully swaps collateral, creates the pool, and redeems after one-atom donations to all three vaults and an external token burn.
- Inspected desktop and mobile screenshots of launch recovery and treasury. Confirmed the pending-launch submit button is disabled, Escape closes the dialog, and there is no horizontal overflow or framework error overlay. A simulated treasury refresh failure correctly identifies the last verified snapshot. Pending-launch visuals used an inert preview wallet; no public-chain transaction was signed or submitted.

## Remaining release requirements and limits

1. Upgrade the program and deploy the matching client/IDL together. Existing global, curve, and DBC registry layouts are unchanged. Existing deployments do not gain these protections from source changes alone.
2. Publish an approved settlement policy for every supported quote/collateral pair. Rates expire within five minutes; the supplied administrator script publishes four-minute rates. Settlement pauses without a fresh policy. Market selection and rate quality depend on the administrator; this is not an autonomous oracle. Instructions are in [verification.md](verification.md).
3. A complete DBC launch-to-migration-to-redemption transaction sequence and issuer-specific Token-2022 behavior still need validation on the intended deployment. The local integration run covers the legacy path and actual DAMM v2 CPIs; shared pricing guards and DBC timing have native test coverage.
4. The production dependency scan still reports 24 affected packages: 8 high and 16 moderate, including inherited reports. These were present before the fixes. High-severity advisory sources include transitive `bigint-buffer`, `toml`, and `postcss`. The registry offers no compatible automatic fix for several SDK paths and suggests major changes/downgrades for others. No dependency overrides or SDK migration were applied in this patch; these reports need separate reachability review and remediation before production use.
5. Browser recovery depends on retaining local storage and using a browser with Web Locks. Clearing storage loses automatic recovery; users should verify wallet history before launching again. A pending record stores public launch details, never mint private keys.

No additional unresolved source-code defect was confirmed in the changed paths during this re-audit. This is a scoped engineering review with the coverage above, not a certification of production security.
